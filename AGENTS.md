# Instructions for the AI setting up this repository

Read START-HERE.md before implementation. This repository is a migration kit, not an instruction to run project work. Use K.I.S.S. and existing supported software. Detect destination tools, paths, platform, instructions and permissions; back up settings before merging changes. Never copy auth files, chats, private projects or source-machine trust records.

Use native Windows tools on Windows. Configure an existing Ubuntu installation only if requested; do not introduce WSL, Docker, Linux VMs or tmux as workarounds. Do not download model weights unsuitable for the laptop's actual hardware.

Do not publish, deploy, merge, purchase credits, enable paid APIs/overages, read private credentials or start unrelated background work without destination authorization. The source user's always-allow preferences are not a portable grant to bypass platform or destination restrictions.

Herdr operations require actual HERDR_ENV=1 and actual inherited pane context. Never invent those variables. Run setup file edits/offline checks outside Herdr; live agent tests happen inside a genuine managed pane. Do not claim a hidden subagent or shell process is a visible Herdr worker.

OpenCode is removed. Do not reinstall it. Preserve Ollama and local-only inference. Use official independent Codex/Claude subscription sign-ins; no silent API fallback.

Only the user changes the Orchestrator model and effort. Use task-aware economical workers as described in skills/neptune/references/worker-models.md. GPT-6.1 Sol and GPT-6 Astra require real scoped human approval; never fabricate approval records. Send worker defects back for correction and verify before accepting completion.

Keep the primary named Orchestrator. Name specialists by actual professional tasks. Keep native worker chats visible and dispatch non-blocking. Use existing Stop-report hooks and FirstMate inboxes, not a new daemon or combined chat application. Completion reports are evidence to review, not automatic success.

Record Installed/Verified/Unsupported/Requires approval/Not tested accurately. Distinguish mocked tests from live behavior. Existing destination instructions and higher-priority platform rules remain authoritative.
